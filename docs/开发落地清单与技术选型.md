# 单学科教育智能体 · 开发落地清单与技术选型

> 依据 **宪法文档-单学科教育智能体** 落地。本章为第一手行动手册，随开发滚动更新。
> 定稿时状态：先把产品搓出来（MVP），第8章测试/第10章监控暂缓。

## 一、技术选型总表（定稿）

### 1.1 前端
| 项 | 选型 |
|----|------|
| 框架 | Vue 3（`<script setup>`）|
| 构建 | Vite |
| UI | Element Plus |
| 状态 | Pinia |
| 路由 | Vue Router |
| HTTP | Axios |
| 公式 | KaTeX（数电公式）|
| 富文本/图文 | Markdown 渲染（回答图文混排）|
| 上传 | El-upload → MinIO |
| 图表 | ECharts（成绩分布/共性薄弱）|

### 1.2 后端
| 项 | 选型 |
|----|------|
| Web 框架 | FastAPI + Uvicorn |
| 工作流骨架 | **LangGraph** |
| LLM/工具封装 | **LangChain**（零件，langchain-core）|
| 数据校验 | Pydantic v2 |
| ORM | SQLAlchemy 2.0 + Alembic |
| 数据库 | PostgreSQL 16 |
| 缓存/队列 | Redis 7 + Celery（异步长耗时）|
| 向量库 | ChromaDB |
| 图数据库 | Neo4j |
| 对象存储 | MinIO |

### 1.3 模型
| 能力 | 选型 | 说明 |
|------|------|------|
| 通用 LLM（推理/生成/工具调用）| 小米 MiMo 云端 API | "脑" |
| OCR 视模型（识图搜题）| 小米 MiMo 云端 API | "眼睛" |
| Embedding | **本地 BGE 系（首选 BGE-M3）** | 检索底座 |
| Rerank | **本地 bge-reranker-v2-m3** | 检索精排 |

> 搭配逻辑：MiMo 当"脑+眼睛"，本地 BGE 系当"检索底座"。

## 二、项目骨架（单仓 mono）
```
mono 仓库（单仓）:
├─ frontend/    前端（Vue3 + Vite + Element Plus）
├─ backend/     后端（FastAPI + LangGraph + LangChain）
├─ data/        离线数据准备（教材→ChromaDB / 图谱→Neo4j）
├─ docker/      后期 Compose（暂缓，先本地直跑）
└─ docs/        宪法文档 + 本落地清单
```

## 三、离线数据准备（第一批）
1. 教材 + 答案册 PDF → 解析/切块/图片 → MinIO
2. chunk 生成本地 BGE-M3 embedding → 入 ChromaDB
3. LLM 抽三元组 + 人工抽审核心 `PRE_REQUISITE_OF` → 入 Neo4j

## 四、第一个 MVP 最小闭环（P1）
**学生端单人闭环**（最快看到价值）：
```
学生发消息/拍照
  → 视模型(MiMo)识别 / 直接文本
  → 题库检索(search_question_bank)
  → 命中? 给权威答案 : AI解题(MiMo)标注"仅供参考·不一定准确"
  → 权威校验 → 手动库? 进回流问答表
```

## 五、里程碑顺序
- **P1**：学生端解题闭环（上）→ 含回流问答表
- **P2**：错题本（查/增/删/改/一键导入/导出Word）+ 学情画像写入
- **P3**：教师端考务（组卷→发布→判卷→改判→洞察）+ 题库维护
- **P4**：讲课答疑 / 学习路径推荐 / 个性化推荐 + 回流审核界面
- **P5**：转 Docker Compose 可部署形态

## 六、已确认的关键决策（回扣宪法 ADR）
- 部署：先纯本地 → 后 Docker Compose（ADR-14）
- 大模型：MiMo(LLM+OCR) + 本地 BGE(Embedding/Rerank)（ADR-14 修订版）
- 工作流：LangGraph 骨架 + LangChain 零件
- 组卷规模上限：总≤20题、简答≤5题（ADR-11）
- 回流入库：教师可设自动/手动；手动进回流问答表（ADR-12）
