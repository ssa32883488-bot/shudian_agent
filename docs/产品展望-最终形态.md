# 学灵伴 · 最终产品展望

> **定位**：面向数字电子技术的校内部署助学智能体。  
> **形态（竞赛提交版）**：学生端 + **管理端**（**砍掉教师/考务端**）。  
> **一句话**：教材 RAG + 知识图谱支撑自由问答；学情驱动自适应练习与错题本；管理端经营题库与回流审核。  
> **范围权威**：与下文旧「教师端」冲突时，以 `产品范围-学生端与管理端.md` 为准。

## 1. 学生端终局

### 1.1 按章节 / 大纲学习（有计划的 AI 教师）

**页面形态**（对标学习通「课程学习」）：

| 区域 | 内容 |
|------|------|
| 左侧目录树 | 本校大纲裁剪后的学科目录（可跳过整章或某节，如「不学第九章」「不学第八章第四节」） |
| 主区教材 | 当前节教材原文可读；可切换查看知识图谱可视化 |
| 进度 | 章节/全书学习进度条；未入班用户不可进入本模块（见 §1.4） |
| 学习会话 | 与 AI 教师的结构化授课互动 |

**学习体验（场景复现）**：

1. 学生打开「第一章 · 数制和码制」，AI 教师从第一节起按顺序讲授。  
2. 讲授中穿插提问、反问；调用课本例题、图谱关联课后题，让学生答或由 AI 精讲。  
3. 举一反三、讲后即练；根据作答对错、过程瑕疵**实时更新本节/本章学情**。  
4. 学完一章 → 生成本章学情报告。  
5. 评价偏低 → 学生可要求 AI 出题，或从题库抽相关题；用正确率与解题细节反复巩固，直到掌握。

**与自由问答的分工**：本模块是「课程制、有状态、有进度」的护航学习；自由问答是无课表约束的自习室。

#### 对应 AI 工作范式（回答你的范式问题）

自由问答用 **ReAct** 合适；**按章系统学不适合纯 ReAct**。更贴切的是组合范式：

| 层次 | 范式 | 作用 |
|------|------|------|
| 外层编排 | **Stateful Tutor / Plan-and-Execute**（有限状态机 + LangGraph） | 管「讲到哪、该练还是该讲、是否可结章」——进度与教案节奏 |
| 课内单步 | **Tool-Augmented Generation**（按需调工具，不必每步 Thought→Act） | RAG 原文、图谱取题、例题、判分工具 |
| 互动策略 | **Socratic + Mastery-based**（苏格拉底提问 + 掌握度门槛） | 提问/反问、错因归因、未达标则加练 |
| 学情写入 | **Memory 写回**（长期画像） | 每轮反馈更新掌握度；章末聚合报告 |

可记成一句话：

> **按章学习 = Curriculum Agent（课程状态机）+ 课内工具调用 + 掌握度门禁**  
> **自由问答 = ReAct 探索 Agent**

不要把「整章教学」做成单次超长 ReAct：token 贵、节奏易漂。应把「当前节目标 / 已讲要点 / 待练题 / 本节掌握度」放进**会话状态**，每轮只推进一小步。

#### Token 与模型策略（本模块特供）

- 支持学生在个人设置中填写自有 API Key：**Kimi / 豆包 / DeepSeek**（BYOK）。  
- 后端按提供商规范调用；本模块涉及教材图、手写/拍照作答时，**由后端自动选用对应视觉能力**（用户无感切换）。  
- 未填 Key 时走平台默认模型（竞赛/试用配额）；填 Key 后消耗用户额度，利于控成本与大规模试用。

---

### 1.2 自由问答（自由的 AI · ReAct）

- 标准对话框 + **历史会话列表**。  
- 可问知识点、解题、搜题、概念辨析等任意学科相关问题。  
- **范式：ReAct**（检索题库 / RAG / 绘图与校验工具 → 观察 → 再推理）。  
- 与系统学共享学情底座：这里产生的错题、掌握度变化，写入同一套学情与错题本。

---

### 1.3 学情板块

- **知识点掌握度**、**错题本**、多维图表（进度、章掌握、薄弱点等）。  
- 错题本可被「按章学习」「自由问答」增删改查。  
- 学情内容可**导出学情报告**；错题本可**导出**便于打印自练。

---

### 1.4 登录与班级码

| 状态 | 可用能力 |
|------|----------|
| 已注册，**未填班级码** | 仅 **自由问答**；不可进入按章系统学 |
| 在个人设置中输入班级码并加入班级 | 解锁按章学习、考试、完整学情中的班级相关视图 |

班级码是「校本大纲 + 班级学情 + 考试」的准入钥匙，不是登录门槛。

> **竞赛提交版注**：不做校本大纲裁剪与考试闭环；班级码主要用于班级学情。详见 `产品范围-学生端与管理端.md`。

---

### 1.5 考试板块

- 作答教师发布的试卷：填写答案、上传作答图片等。  
- 服从教师端发布/收卷规则；成绩展示遵循「AI 辅助、教师决策」红线（不对外出具官方认定成绩）。

## 2. 教师端终局

### 2.1 班级学情

以班级为单位：

- 查看学生学习进度、各章掌握程度、共性薄弱点等。  
- 导出班级/个人相关报告，服务备课与辅导。

数据主要来自：按章学习轨迹、练习与考试结果、错题沉淀——而非仅聊天摘要。

---

### 2.2 试卷与考试管理

- 试卷题量：**1–20 题**；其中**大题最多 5 道**；题型支持选择、填空等（及既有大题形态）。  
- 考试管理：发布到班级、设置收卷时间或手动收卷、查看答卷与分析入口。

---

### 2.3 考务 Agent（悬浮球 · 可多 Agent 协作）

**交互形态**：右下角悬浮球 → 点击对话；可看历史；执行任务后**按需自动刷新**对应业务界面（如新试卷出现在考试管理页）。

**能力整合**（对外一个球，对内可多专家协作）：

| 能力 | 说明 |
|------|------|
| 出题 | 题库抽题，或 AI 生成后入卷/待审 |
| 组卷 | 与教师确认题型、数量（受 1–20 / 大题≤5 约束） |
| 改卷面 | 对话中对已生成试卷题目增删改查 |
| 判卷 | 收卷后指挥 AI 批改 |
| 考试分析 | 单次考试学情、薄弱点解读 |

**典型流程**：

1. 教师：「结合当前班学情，按薄弱点出一套卷。」  
2. Agent 询问题型配置并提示上限；教师：「十选五填五道大题」或「只出五道大题」。  
3. Agent 组卷完成 → 对话内告知；试卷出现在**考试管理界面**。  
4. 教师在界面审阅、设发布时间与收卷；仍可通过对话让 Agent 改题。  
5. 发布并收卷后，教师可说「去判卷并分析」，或在该场考试上点「学情分析 / 判卷」**一键唤醒**同一 Agent。

---

### 2.4 题库维护与权限（替代独立管理端）

**默认资产**：课本习题整理入库，打好标签并挂接知识图谱，供检索与组卷调用。

**维护主体**：以**学校**为题库边界（本校教师共享一库）；**不设独立管理站点**。

**推荐权限模型（校级双角色）**：

| 角色 | 题库 | 其它 |
|------|------|------|
| **普通教师** | 可提交新增/修订建议；可对本班教学相关题目做有限维护（或仅「建议入库」） | 本班学情、组卷考试、回流审核（可配置） |
| **校级管理员教师**（唯一或少数账号，仍走教师端） | 题库最终增删改查、批量治理、默认库版本 | 大纲模板、班级码策略等少量「系统设置」入口挂在教师端「学校设置」 |

原则：

- **避免「所有老师无审核直删公共题」** → 防误删与质量漂移。  
- **避免另建运营中台** → 管理员仍是教师账号的一种权限，页面仍在教师端。  
- 学生解题回流：优质问答对进入待审队列，由教师或校级管理员审核入库（延续现有回流设计）。

## 3. 架构原则（终局约束）

1. **界面即路由**：学生在「系统学 / 自由问 / 学情 / 考试」、教师在「学情 / 试卷 / 题库」各调对应 Agent；师生 Agent 解耦，**共享学情与题库数据底座**。  
2. **两条成绩线不混淆**：正式考试成绩由教师发布决定；学习过程中的评分、章报告仅为形成性反馈。  
3. **大纲裁剪是校本差异的第一公民**：目录树、学习路线、组卷范围、学情统计均以教师上传/绑定的大纲为准。  
4. **无独立管理端**：运维最小化；能挂在教师端「学校设置」的不另开产品线。  
5. **通用大模型为主力 + 工具/RAG/图谱**；章节学支持 BYOK 以降本。

---

## 4. 用户价值一句话

| 角色 | 终局体验 |
|------|----------|
| 学生 | 有课表地学完校本大纲，随时问、能考试、能看见并打印自己的掌握度与错题。 |
| 教师 | 一个悬浮球聊完出卷与分析，班级薄弱点看得见，题库在校内越用越厚。 |
| 学校 | 一校一库一大纲，部署清晰，无需再养一套运营后台。 |

---

## 5. 与竞赛叙事的对齐

- **助学**：系统学（Curriculum Agent）+ 自由问答（ReAct）+ 学情与错题。  
- **助教**：考务 Agent 全流程 + 班级洞察。  
- **垂类**：数电教材原文、图谱、默认题库、校本大纲裁剪。  
- **可复制**：按校部署；大纲与班级码隔离校本差异；题库权限校内自治。
