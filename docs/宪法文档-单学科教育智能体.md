# 第1章 明确需求（已定稿）

## 1.0 需求边界裁定（"成绩判定/学术评价"的边界）

系统中存在**两条独立的"成绩判定"线**，绝不可混淆：

| | 线A：正式教学流程（教师主导，AI辅助） | 线B：学生主动问答（用户主导，AI反馈） |
|---|---|---|
| 触发 | 教师组卷→发布→学生考试 | ①上传 ≤5MB 题目/试卷文件(word/pdf等) ②用户主动询问 |
| AI角色 | 组卷助手 + 判卷助手 | 答题反馈 + 评分建议 |
| 判定性质 | 辅助教师，最终是否公布由教师决定 | 建议性反馈，非正式教学决定 |
| 共同红线 | AI 不面向第三方/学术机构出具"官方认定"；判定是建议而非最终决定 | 同左 |

## 1.1 一句话定义
> 一个**面向数字电子技术学科的教学闭环智能体**：以学科内容为底座，借通用大模型的核心能力（垂类微调为辅助），围绕学生"听课→练题→搜题→解题→沉淀"，叠加教师"组卷→发布→判卷→看数据"，构建 **"教、学、考 + 题库沉淀"** 的完整闭环。

## 1.2 服务对象与角色
| 对象 | 定位 | 核心场景 | 高频诉求 |
|------|------|----------|----------|
| 学生 | **主攻（助学）** | 讲解答疑、拍照搜题、解题、自主练习 | "这题怎么解？""我做得对吗？""我的前置知识够吗？" |
| 教师 | **次要（助教）** | 组卷、发布、判卷、数据洞察 | AI帮我出一套"中难度、考时序逻辑、20题"的卷子；这班薄弱点在哪 |
| 助研 | **不涉及** | — | — |

## 1.3 核心闭环（本智能体的灵魂）
```
拍照/打字搜题
      │
      ▼
 ┌─ 题库命中？ ──是──► 直接给答案+解析（已达标权威问答对）
      │否
      ▼
   解题（借通用大模型，严谨校验）
      │
      ▼
  答案权威性达标评估 ──否──► 只作反馈，不入库
      │是
      ▼
   优质问答对 回流题库（类比客服FAQ沉淀）
```
> **类比**：像客服系统把没见过的用户提问沉淀成 FAQ，这里"库中没有的题被解出并校验通过后"回流成新的权威问答对，自生长。

## 1.4 Agent 要交付的最终结果（输出）
1. 学科问讲解（讲课）——有据，引用课本原文/图片
2. 解题答疑（做题）——分步、可校验、有权威答案
3. 拍照搜题——命中题库给结果，未命中现场解题并可回流
4. 学习路径推荐——基于知识图谱"先补什么"
5. 教师组卷——按题型/难度/规模(上限)/范围 自动组卷入试卷库
6. 在线考试 + AI判卷——学生传图/打字作答，AI判卷，教师看数据
7. 成绩数据洞察——共性薄弱点、班级分布
8. 专业绘图——状态转换图/卡诺图等（Tier工具层）

## 1.5 边界：什么事情不应该由 Agent 做（反目标）
- ❌ 不面向第三方/学术机构出具"官方认定"成绩
- ❌ 正式成绩的公布与生效，决策权始终在教师（AI只是辅助判卷）
- ❌ 不替代教师做最终育人/学术评价决定
- ❌ 不做从零自研复杂绘图引擎（工具层已定：不造引擎，造规范+治理）
- ❌ 不碰非数电学科（单学科定位，多学科需另立实例）
- ❌ 不做无出处的"权威结论"（公式/规范必须RAG检索验证）
- ❌ 解决方案不依赖自研垂类大模型为唯一引擎（通用大模型为主力，微调是配角）

## 1.6 技术定位（原则性表述，具体窄任务微调取舍留待开发期定）
> 本质是**借通用大模型的通用能力为主**（推理、理解、生成、工具调用），**微调垂类大模型为辅**（在特定高频、窄域任务上做成本/质量/延迟优化，见工具层 Tier-C 思想）。**不追求"全自研重模型"**。具体在哪个窄任务上做微调，需在具体开发中依据实测确定。

## 1.7 成功标准（第8章会再量化）
- 跑通 **拍照搜题→解题→优质问答对入题库** 自生长闭环
- 完成 **组卷→发布→在线考→AI判卷→数据洞察** 全链路
- 可作为**学科垂类大模型 + 智能体应用**的参赛/落地交付物

# 第3章 设计 Agent 本体（定稿，教师端=单一考务Agent·悬浮球）

> 本章回答"这个 AI 是谁、怎么思考、怎么说话"。结论：**界面=路由 + 解耦平行 Agent + 共享学情数据底座**。

## 3.0 架构级决策：界面即路由的"平行多 Agent"

学生对老师的 AI **解耦、互相独立，仅共享底层数据**。分发由**前端界面**决定（用户在哪个界面就调哪个 Agent），**不做复杂总调度/意图理解再分派**。

```
前端界面（谁在用、在哪 → 决定路由）
  ├─ 学生端界面 ──► 助学导师 AI（1套提示词，调内部工具）
  ├─ 组题界面  ──► 组卷 AI
  ├─ 收卷/数据界面 ─► 考务 AI（判卷模式 / 洞察模式）
  └─────────── 共享学情数据底座（判卷结果/错题/掌握度/轨迹）
                       ▲
                助学导师读取（个性化）
题库维护AI = 校验步骤（不设独立Agent，回调进解题流程）
```

## 3.1 学生端主人格：学科助学导师（数电）

**身份**：数字电子技术学科的 AI 讲学导师

**目标**：
- 让概念、解题思路**真正被理解**，而非只给答案
- 回答有据、讲解分步

**回复方式可配置**（学生可设置）：
- 模式①：直接回复答案
- 模式②：带引导的提问（苏格拉底式）

**核心行为规则（Rules）**：
- 讲解优先"分步、类比、化繁为简"
- 涉公式/定理/规范，**必须 RAG 检索验证**，不编造
- 遇到题库外新题 → 先标注"AI解答·仅供参考·不一定准确"再解题（衔接信任分级）
- 记得学生画像（第5章记忆）：个性化对照

**决策原则**：
- 该查前置依赖 → 走知识图谱
- 该画图讲解 → 调绘图工具
- 该给个性化 → 读学情库

**输出规范**：结论 → 依据 → 步骤（必要时配图）；图片来源引用课本，权威结论标出处

## 3.2 教师端：单一考务 Agent（悬浮球常驻 · 一个对话窗口按需路由）

- **形态**：教师端所有 AI 能力收敛为**一个"考务 Agent"**，作为**任意界面右下角的常驻悬浮球**入口；点开即一个对话窗口（历史对话可回看）。
- **路由**：根据教师需求在内部子能力间路由（出卷 / 判卷 / 洞察 / 改判）。
- **执行与落位**：Agent 执行任务时，结果落到对应业务界面（如出卷 → 试卷管理界面出现新卷），对话窗口内给出链接可跳转进入查看。
- **短期记忆**：跟随对话窗口本身（不随浏览页面切换），打开=一个会话，切走再点开仍看历史对话。

### 子能力路由表
| 子能力 | 触发/指令 | AI 做的事 | 产出/落位 |
|--------|-----------|-----------|-----------|
| **出卷** | "出一套中难度、考时序逻辑、20题" | 问答确认题型/难度/规模(上限)/范围→组卷 | 试卷出现在试卷管理界面；对话给链接 |
| **判卷** | （对应试卷状态→收卷后）"AI判卷" | 按评分标准给每题得分+批注+该卷小结 | 原始判卷结果存学情库 |
| **改判** | 教师抽检已判卷发现判错 | 教师手动改判（客观题改对/主观题改分） | 更新判卷结果 |
| **洞察** | 打开某次考试且有数据后对话 | 基于已存判卷结果分析：共性薄弱点/分布/归因/建议 | 班级/某次报告解读 |

### 试卷状态机（约束前置条件）
```
组卷/存库 → 已发布(学生作答中) → 已收卷 → [可判卷]
已收卷未判完 → 不可数据分析
已判完 → [可洞察分析/改判] 
```
1. **没收卷 → 不能判卷**
2. **没判完卷 → 不能数据分析**
3. **洞察只读已判结果，不重复判卷**

## 3.3 系统级：题库维护（一个校验步骤，非独立 Agent）
- 判断"AI 现解"答案**权威性是否达标**来决定是否入库（衔接第2章 A4/A5 与信任分级）
- 作为工作流内校验环节，回调进助学/解题流程

## 3.4 完整拓扑与共享数据底座
```
前端界面（谁在用、在哪 → 决定路由）
  学生端：助学导师 AI（一个对话窗口，可配置回复方式）─┐
  教师端：考务 Agent（右下角悬浮球常驻，一个对话窗口按需路由出卷/判卷/洞察/改判）─┤
  答题   ：纯表单界面（与AI无关），学生看AI判卷结果                              │
  题库   ：教师可维护（增删改查/批量导入导出），学生仅查                         │
                                                   ▼
            共享学情数据底座（判卷结果/错题/掌握度/轨迹/画像）
```
- 各 Agent 解耦，仅通过共享学情底座"数据相通"
- 题库维护AI = 校验步骤（非独立 Agent）

# 第4章 接入知识（定稿）

> 本章决定"这个 AI 凭什么懂数电、回答凭什么有据"。核心分层：**数据准备离线完成（开发期一次性嵌入），运行时只做检索生成**；后台不维护解析/切分管道。

## 4.0 知识体系两大支柱 + 题库资产

| 支柱 | 存储 | 解决什么 | 准备与维护 |
|------|------|----------|-----------|
| **RAG-向量知识** | ChromaDB + MinIO | "回答有据"——引课本原文/图 | 离线做好，开发期嵌入 |
| **知识图谱** | Neo4j | "先学什么 / 考什么" | 离线构建，开发期嵌入 |
| **题库（资产）** | 数据库 | 搜题命中 / 组卷来源 / 回流沉淀 | **教师持续维护** |

> 支撑关系：RAG→A1讲课/A2解题/A3拍照搜题"有据"；图谱→A6路径推荐/⑥个性化前置推理；题库→A3搜题/B1组卷/A5回流。

## 4.1 分层原则（本章灵魂）
- **数据准备层（离线 / 人做 / 开发期一次性）**：PDF解析、切原子块、段落切分标记、图片传 MinIO + 多模态生成描述、Embedding；图谱离线抽取 + 人工抽审
- **运行时层（代码做 / 每次提问）**：仅"多路检索 + 重排序 + Prompt + 生成"
- **后台不维护解析/切分管道**；教学内容由教师离线提供与更新

## 4.2 RAG 检索生成（运行时唯一代码段：多路检索 + 重排序）
```
用户问题
  → Embedding（语义）
  → 多路召回：
      向量路(语义) + 关键词/BM25路(术语精确) + [图谱路(知识点/前置)]
  → 合并去重 → 候选池
  → Rerank 精排（问题 × 候选 配对打分）
  → Top-K 真正进 Prompt
  → 构造Prompt(引用 text_content + 图URL)
  → 大模型生成图文混排回答
```
> 多路检索保证"卡诺图、竞争冒险"等精确术语能命中；Rerank 提升语义相近但术语关键的排序质量。

## 4.3 知识图谱
- 本体：`Concept / Chapter / Exercise / Formula`；关系 `BELONGS_TO / PRE_REQUISITE_OF / TESTS / HAS_FORMULA`
- **题目↔知识点↔前置依赖贯通**（核心）：学生做错题→反查知识点→定位前置缺失→个性化；教师看班级薄弱→定位知识点/章节→考务洞察
- 构建：**离线**（LLM 抽取 + 人工抽审核心关系 `PRE_REQUISITE_OF`），开发期嵌入

## 4.4 知识范围
- **一本教材 + 该教材的习题答案册**；**无历年卷**
- `knowledge_tags` 打标：**LLM 自动 + 人工抽审**

## 4.5 题库（可维护资产）
- **定位**：不止是问答回流产物，更是**教师可主动经营的数据资产**，构成**资产知识壁垒**
- **教师端（可维护）**：增 / 删 / 改 / 查 + **批量导出** + **批量导入**（可按自定格式）；未来可按规定格式持续导入沉淀
- **学生端（仅可查）**：只读
- **关联**：每道题打 `knowledge_tags` → 形成"题目→知识点→章节→前置依赖"贯通
- > 题库的管理接口/权限/导入导出解析，其落地见第6工具/第7工作流/第9部署；本章仅定定位与边界

## 4.6 权威性治理（衔接信任分级）
- 检索到才引用；未检索标"参考"
- 入库问答对/组卷题目必须能关联到权威来源（课本/章节/已入库）

# 第5章 接入记忆（定稿）

> 本章让 Agent "记住用户"。核心：**Knowledge 记世界（第4章），Memory 记用户**。长期记忆 = 读写"共享学情数据底座"（不另起炉灶），**只存聚合后的画像**。

## 5.1 短期记忆（当前会话）
- 存：当前对话上下文、最近几轮消息、当前任务状态、当前变量
- 归属：**各自独立的对话窗口**（学生端助学窗口 / 教师端考务悬浮球窗口）
- 会话内天然延续；点开即一个会话，历史对话可回看（类 DeepSeek 历史列表）

## 5.2 长期记忆（跨会话 · 聚合画像，非流水）
> 只存**聚合态**，不存原始作答流水（可回溯性让位于简洁与可维护）。
> **补充（ADR-M1～M3）**：对话原文不上云；满轮次后的**对话摘要**可入库，但摘要仍属**对话隐私**（仅本人可读）。从摘要与练习/考试硬信号沉淀出的**学情画像**非隐私，师生同构可见。

- **基础画像**：专业、年级、目标、回复方式偏好（学生）
- **错题本**：踩过的坑（对应第2章 A8）
- **掌握度**：各知识点当前掌握度（聚合；键对齐 concept / 知识点名）
- **努力/学习轨迹**：练习频率、时长、趋势（聚合画像）
- **判卷结果**：学生可查自己的判卷；教师可查学情+判卷（可改判）
- **对话摘要（隐私）**：`memory_summaries`，教师不可读；仅用于沉淀画像与本人回看

## 5.3 与学情数据底座的关系（关键）
- 长期记忆**不是新造存储**，而是**读写第3章共享学情数据底座**（判卷结果/错题/掌握度/轨迹/画像）+ 隐私侧摘要表
- 助学导师"记得学生" = 从底座读聚合画像 + 浏览器短期会话拼装
- 考务"学生端看个人"与教师端"看班级"读同一底座，视角不同；考务 Agent 默认读班级 `class_rollups`

## 5.4 隐私与权限矩阵（衔接第1章红线 + 定稿补充）

| 数据 | 学生可见 | 教师可见 |
|------|----------|----------|
| 学生对话内容/隐私 | 本人 | **不可见** |
| 学生学情（掌握度/错题/轨迹） | 本人 | **可见** |
| 学生判卷结果 | **本人可见** | **可见 + 可改判** |
| 班级聚合数据（成绩分布/共性薄弱） | — | 可见 |

- 红线：教师**不读取学生对话隐私**；教师可看学情 + 判卷结果
- 学生只能看**自己**的判卷/学情（不越权看他人）

## 5.5 跨会话 / 跨界面策略
- **跨会话**：靠**长期记忆（聚合画像）**，不做逐条对话记忆
- **跨界面（作废概念）**：不存在多个 AI 界面切换上下文问题——学生端=一个助学对话窗口，答题是纯表单界面（与AI无关），教师端=一个考务悬浮球对话窗口
- 短期记忆只属于各自对话窗口，不跨窗口串

# 第6章 接入工具（定稿）

> 本章把第2章能力域从"动作清单"变成"Agent 可调用工具集"。**模型负责思考，工具负责执行**。

## 6.0 工具分类总览
| 类 | 工具 | 服务Agent | 能力域 |
|----|------|----------|--------|
| 知识检索 | 多路检索(RAG)、Rerank、图谱查询、题库检索 | 助学/考务 | C2/C3/C5 |
| 解题答题 | OCR视模型、答案权威校验、专业绘图(Tier) | 助学 | ②③C1 |
| 考务执行 | 组卷、判卷、改判、成绩导入 | 考务 | ④B6 |
| 资产/学情 | 题库增删改查/导入导出、学情画像、错题本、学情报告 | 助学+考务 | ⑥资产C6 |

## 6.1 绘图工具（沿用 Tier 三档）
- Tier-A：推理级绘图（Schematex等），开放度高、需"理解题意再画"
- Tier-B：确定性绘图（Kmap/真值表等），规则死、教材级稳定
- Tier-C：窄域小模型，高频格式窄、省成本
- 统一门面 `draw_*`；对内 Tool Gateway：`tier`/引擎/Schema/产物目录
- 统一出参：`{ ok, artifact(svg), meta, engine, tier, warnings }`

## 6.2 检索生成工具（运行时链路，第4章）
- `retrieve_multi_rerank(question)` → 多路召回+Rerank→Top-K
- `search_question_bank(text)` → 题库命中检索
- `graph_query(concept)` → 知识图谱（前置依赖/知识点关联）

## 6.3 解题与回流工具（衔接信任分级）
- `solve_problem(question)` → 解题流程
- `validate_authority(answer, source)` → 权威校验，决定能否入库
- **OCR 拍照 = 视模型**：图片直接理解识别题目，不拆"OCR转文本"两步；识别后→题库检索/解题

## 6.4 考务工具（考务 Agent 调用）
- `generate_paper(题型/难度/规模/范围)` → 组卷入试卷库
- `grade_answer(试卷/参考答案/学生作答)` → 判卷
- `update_grade(试卷/题/学生, 新分数)` → 教师改判
- `sheet_report(paper_id)` → 判卷结果汇总（供洞察）

## 6.5 题库 / 学情资产工具
**题库**
- 教师端：`bank_crud`、`bank_import(规定格式)`、`bank_export`（教师可维护=资产）
- 学生端：只读检索

**学情画像（第5章聚合画像）**
- `read_profile(student)` / `update_profile(student, delta)`

**错题本（学生端核心，助学导师可增删改查）**
- `mistake_list` 查 / `mistake_add` 增（含**考试结果一键导入**）/ `mistake_delete` 删 / `mistake_update` 改
- `mistake_export_word` 导出错题 Word

**学情报告（教务端 / 考务 Agent）——两种口径都要**
- `sheet_report_course_by_paper(paper_id)` → 按某次考试的报告
- `sheet_report_course_overview(course_id)` → 按课程跨次滚动的班级报告（共性薄弱点/分布/归因/建议，可导出）

## 6.6 工具与 Agent 绑定（衔接第3章解耦）
| Agent | 可用工具集 |
|-------|-----------|
| 助学导师 | 知识检索 + 解题答题绘图 + 读学情画像 + **错题本全套（查/增/删/改/导入/导出Word）** |
| 考务 Agent | 考务执行（组卷/判卷/改判/洞察）+ 题库维护(教师) + 读学情 + **学情报告（按次+按课程）** |
| （题库校验步骤）| 答案权威校验 |
| 权限红线 | 学生只读题库/错题本仅本人；教师可写题库/看学情判卷；教师不见对话隐私 |

# 第7章 设计工作流（定稿）

> 本章把前几章能力编排成"Agent 一步步行动"的流程。用 LangGraph 的节点/边/条件分支表达。三条主线：学生端解题闭环（含回流）、教师端考务闭环、以及贯穿的信任分级的校验。

## 7.0 工作流总览（主线）
- **学生端（助学导师）**：讲课答疑 / 解题答疑 / 拍照搜题 / 学习路径推荐 / 错题本管理 / 个性化推荐
- **教师端（考务 Agent）**：AI组卷 / AI判卷 / AI改判 / 学情洞察 / 题库维护 / 回流问答审核
- 共用源：解题主流程（打字与拍照共用，OCR仅输入源差异）

## 7.1 学生端核心工作流

### W1 讲课答疑
```
学生提问 → 意图判断 → RAG多路检索+Rerank → 构造Prompt(含图引用) → 生成图文混排回答
（讲解概念/原理，涉公式规范须检索验证）
```

### W2/W3 解题答疑 & 拍照搜题（共用一条主流程）
```
输入源: 打字 或 拍照(视模型识别→提取题面)
   ↓
题库命中? ──是──► 直接给权威答案+解析（已收录）
   ↓否
AI解题（标注"AI解答·仅供参考·不一定准确"）
   ↓
答案权威性校验
   ├─ 未达标 → 仅作为反馈，不入库
   └─ 达标 ──► 回流入库策略（见7.3）
```
> OCR视模型把图片变成题面文本后，与打字走同一条解题主流程。

### W4 学习路径推荐
```
"我学X缺什么" → 知识图谱查询(X的前置依赖) → 定位缺失 → 推荐学习路径
```

### W5 错题本管理
```
学生操作 → 查/增/删/改/一键导入(考试结果)/导出Word
（助学导师调用错题本全套工具）
```

### W6 个性化推荐
```
读学情画像(聚合) → 定位薄弱知识点 → 推题/提醒复习
```

## 7.2 教师端核心工作流（考务 Agent）

### W7 AI组卷（含规模约束）
```
教师指令 → 问答确认(题型/难度/范围) → 校验规模上限 → 调题库组卷 → 存试卷库(状态)
```
**规模上限（省token约定）**：
- 题型：选择题 / 填空题 / 解答题（简答并入解答题口径）
- 单张卷：**总题数 ≤ 20 道**；**简答题 ≤ 5 道**；其余不限

### W8 AI判卷
```
【状态机前置】必须是"已收卷"状态
学生作答(传图/打字) → 按评分标准判卷→每题得分+批注+该卷小结 → 存判卷结果(学情库)
```

### W9 AI改判
```
教师抽检已判卷发现错 → 改判(客观题改对/主观题改分) → 更新判卷结果 → 联动学情
```

### W10 学情洞察
```
【状态机前置】先判完卷才能洞察
打开某次考试/班级+有数据 → 读已存判卷结果 → 分析(共性薄弱/分布/归因/建议) → 报告(按次或按课程跨次)
```

### W11 题库维护
```
教师操作 → 增删改查 / 批量导入(规定格式) / 导出
```

## 7.3 回流入库策略（题库资产关键决策）
- 教师可设置**自动入库 与否**
- **自动入库**：校验达标 → 直接进正式题库
- **手动入库（默认/推荐）**：校验达标 → 进**回流问答表（待审）** → 教师审核后**选择性入库**

```
AI现解达标
  ├─ 自动入库(教师设定开启) → 正式题库
  └─ 手动入库 → 回流问答表(待审) → 教师审核 → 选择性入正式题库
```
> **正式题库**：已审核、权威，可直接考试/检索。
> **回流问答表**：积累待审候选，教师可维护与审查。详见附录 ADR。

## 7.4 信任分级在流程中的落点
- 题库命中 → "已收录权威答案"
- AI现解未入库 → "AI解答，仅供参考·不一定准确"
- 备考/学情建议 → 建议性反馈
- AI判卷 → 辅助教师，教师复核+决定公布

## 7.5 状态机矩阵（考务前置校验）
| 试卷状态 | 允许操作 |
|----------|----------|
| 组卷/存库(未发布) | 可改卷、可删除 |
| 已发布(作答中) | 学生作答；不可判卷 |
| 已收卷 | **可判卷**；未判完不可洞察 |
| 已判完 | **可洞察分析 / 可改判** |

# 第9章 部署上线（定稿）

> 本阶段以**先把产品搓出来（MVP/POC）**为目标；第8章测试评估与第10章监控迭代暂缓，产品成型后再补，此处占位。

## 9.1 四层架构 + 本项目组件映射

```
第1层 展示层（用户浏览器）
├─ 学生端：助学对话窗口 / 答题界面(纯表单) / 判卷结果 / 错题本 / 学习路径
├─ 教师端：考务悬浮球对话窗口 / 试卷管理 / 班级成绩 / 学情报告 / 题库维护
└─ 技术：Vue3 + Vite + Element Plus
     │ HTTPS（公网）
第2层 接入层
└─ Nginx（反代 / 静态托管 / 权限入口）
     │ HTTP（内网）
第3层 业务层（FastAPI + Uvicorn + LangGraph）
├─ 学生端：助学导师 Agent（LangGraph 编排）
├─ 教师端：考务 Agent（组卷/判卷/洞察/改判）
├─ 解题 / 绘图 / OCR 服务（OCR 视模型另选）
└─ 技术栈：FastAPI + Uvicorn + LangGraph
     │
第4层 数据层
├─ PostgreSQL + SQLAlchemy：业务数据（题库/回流表/试卷/成绩/用户/错题/画像）
├─ Redis：缓存 / 会话 / 任务队列
├─ ChromaDB：向量知识库（RAG）
├─ Neo4j：知识图谱
├─ MinIO：图片/媒体对象存储
└─ 外部云端：大模型 API / OCR / Embedding / Rerank
```

## 9.2 大模型选型（定稿）
| 能力 | 选型 | 说明 |
|------|------|------|
| 通用大模型（推理/生成/工具调用） | **小米 MiMo 云端 API** | "脑" |
| OCR 视模型（识图搜题） | **小米 MiMo 云端 API** | "眼睛" |
| Embedding | **另选** | 向量检索底座 |
| Rerank | **另选** | 检索精排 |

> 搭配逻辑：**MiMo 承担"脑"（推理/生成/工具调用 + OCR 识图），Embedding/Rerank 用专门模型**（检索底座）。混合模型栈。

## 9.3 部署路径（定稿）
- **阶段一：纯本地直跑 Demo**——本机起 FastAPI + 各数据依赖（PG/Redis/Chroma/Neo4j/MinIO + 前端 Vite dev），最快验证产品闭环。**不做本地 GPU 推理**（MiMo 纯云端）。
- **阶段二：转 Docker Compose**——闭环稳定后，用 Compose 编排成可部署形态（更接近生产）。
- 阶段一切换时机：学生端闭环（提问→解题/搜题→回流）+ 教师端闭环（组卷→判卷→洞察）跑通。

## 9.4 异步任务与长耗时
- 大模型推理、判卷、组卷等长耗时任务走 **Celery/Redis 队列**异步，避免阻塞 FastAPI。

## 9.5 落地点（衔接前几章）
- 离线数据准备（开发期）：教材→ChromaDB，图谱→Neo4j（第4章）
- 题库/回流表/试卷/成绩/错题/画像 → PostgreSQL（第4/6/7章）
- 判卷/组卷/洞察/OCR/解题 → 业务层 Agent 服务（第6/7章）

## Appendix C · 术语表
| 术语 | 含义 |
|------|------|
| RAG | 检索增强生成：检索课本知识供大模型引用作答 |
| Rerank | 重排序：将问题×候选配对精排，提升检索质量 |
| 知识图谱 | Neo4j 中"知识点/章节/题目/前置依赖"的节点与关系 |
| 正式题库 | 已审核、权威，可直接考试/检索的题目集合 |
| 回流问答表 | 待审候选：AI现解达标未入正式库，教师审核后选择性入库 |
| 学情数据底座 | 共享的判卷结果/错题/掌握度/轨迹/画像，各Agent经此"数据相通" |
| 错题本 | 学生端个人错题集合，系统学与自由问答均可增删改查/导入/导出 |
| 考务 Agent | 教师端单一悬浮球 Agent，内含出卷/判卷/洞察/改判 |
| 学情报告 | 三类：①按次考试 ②按课程跨次 ③按章形成性（系统学结章） |
| Curriculum Agent | 按章/大纲系统学的有状态助学 Agent（非纯 ReAct） |
| 校本大纲 | 本校裁剪后的章/节目录，驱动学习路线与统计口径 |
| 班级码 | 学生加入班级的准入码；未入班仅开放自由问答 |
| BYOK | Bring Your Own Key：学生自备 Kimi/豆包/DeepSeek Key |
| 校级管理员教师 | 教师端权限角色，负责题库终审与学校设置；非独立管理端账号体系 |
| 学校设置 | 教师端内嵌的少量校级配置入口（替代独立管理后台）|
