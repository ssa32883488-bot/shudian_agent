## 一、RAG系统构建（ChromaDB + MinIO + 大模型）

RAG的目标是：**用户提问 → 找到相关课本片段（文字+图片）→ 大模型生成答案**。

### 第一步：数据预处理（从PDF到“原子块”）

|步骤|操作|技术工具|产出物|
|---|---|---|---|
|1.1|解析PDF，提取文字、图片、表格|PyMuPDF (fitz)|每页的原始文字流 + 图片对象|
|1.2|按“章/节/例题/习题”标题切分文本块|正则匹配（`第X章`、`例X.X`）|逻辑独立的文本块，每块300-800字|
|1.3|提取图片并上传至MinIO，获得访问URL|MinIO Python SDK|`{"fig_id": "ch03_fig_02", "url": "http://minio/..."}`|
|1.4|为每张图片生成文字描述|多模态大模型（Qwen-VL/GPT-4V）|`"图3-2：CMOS反相器的电路结构图..."`|
|1.5|将图片描述“挂载”到所在段落末尾|脚本合并|增强后的文本块（含图片描述和URL）|

**最终产出**：一个包含以下字段的Chunk列表：

json

{
  "chunk_id": "ch03_sec02_block_01",
  "text_content": "组合逻辑电路的竞争冒险现象是指... 图3-2展示了CMOS反相器的结构... [图片描述：...]",
  "media_urls": ["http://minio/static/ch03/fig3-2.png"],
  "chapter": "第三章",
  "section": "第二节",
  "knowledge_tags": ["竞争冒险", "CMOS反相器"]
}

### 第二步：向量化与入库

|步骤|操作|技术工具|产出物|
|---|---|---|---|
|2.1|将`text_content`转为向量|Embedding模型（如`text-embedding-3-small`）|向量数组 `[0.123, -0.456, ...]`|
|2.2|将（向量 + 元数据）写入ChromaDB|ChromaDB Python SDK|ChromaDB中的Collection|

**关键字段设计（ChromaDB Collection Schema）**：

|字段名|类型|说明|
|---|---|---|
|`id`|string|chunk_id|
|`text_content`|string|完整文本（供LLM阅读）|
|`media_urls`|string|多个图片URL，用逗号分隔|
|`chapter`|string|所属章节|
|`embedding`|vector|向量|

### 第三步：检索与生成

|步骤|操作|说明|
|---|---|---|
|3.1|用户提问 → Embedding → 向量|将问题转为向量|
|3.2|ChromaDB相似度检索，返回Top-5|按相似度排序|
|3.3|提取`text_content`和`media_urls`|构成上下文|
|3.4|构造Prompt，调用大模型生成回答|Prompt中包含“请使用Markdown图片语法引用图片”|
|3.5|返回最终回答（含图文混排）|前端渲染|

## 二、知识图谱构建（Neo4j + LLM辅助）

知识图谱的目标是：**存储“知识点A是B的前置知识”、“习题X考察知识点Y”等逻辑关系，用于学习路径推理**。

### 第一步：本体设计（Schema）

在Neo4j中定义以下节点标签和关系类型：

cypher

// 节点标签（Labels）
:Concept     // 知识点，如"卡诺图"
:Chapter     // 章节，如"第三章"
:Exercise    // 习题/例题，如"习题3.12"
:Formula     // 公式/定理，如"8421码"
// 关系类型（Relationship Types）
:BELONGS_TO       // (知识点/习题) -[属于]-> 章节
:PRE_REQUISITE_OF // 知识点A -[前置知识]-> 知识点B （灵魂关系）
:TESTS            // 习题 -[考察]-> 知识点
:HAS_FORMULA      // 知识点 -[包含公式]-> 公式

### 第二步：数据准备（从课本中提取三元组）

不要手工标，用LLM批量抽取。

|步骤|操作|说明|
|---|---|---|
|2.1|按章节打包正文、例题、习题|每包约1500-2000字|
|2.2|设计Prompt，要求LLM输出结构化JSON|Prompt模板见下文|
|2.3|批量调用LLM API，获取所有三元组|注意控制并发，防止限流|
|2.4|对LLM抽取的结果做**关键路径人工审核**|重点审核`PRE_REQUISITE_OF`关系|

**Prompt模板（可直接使用）**：

> **系统**：你是数字电子技术领域的知识工程专家。请从以下课本文本中提取知识图谱所需的三元组。严格按JSON格式输出，不要有多余解释。
> 
> **任务**：
> 
> 1. 识别所有核心**概念**（如“竞争冒险”）、**公式**（如“8421码”）、**典型例题**（如“例3.2.1”）及所属**章节**。
>     
> 2. 抽取以下关系：
>     
>     - `BELONGS_TO`：知识点/习题/公式属于哪个章节。
>         
>     - `PRE_REQUISITE_OF`（**关键**）：识别“学习A之前，必须先掌握B”的逻辑，**特别注意跨章节的依赖**。
>         
>     - `TESTS`：例题或习题主要考察了哪个知识点。
>         
> 
> **输入文本**：  
> [在此粘贴章节内容]
> 
> **输出格式示例**：  
> {  
> "nodes": [  
> { "id": "concept_001", "type": "Concept", "name": "竞争冒险" },  
> { "id": "chapter_03", "type": "Chapter", "name": "第三章" }  
> ],  
> "relationships": [  
> { "from": "concept_001", "to": "chapter_03", "type": "BELONGS_TO" },  
> { "from": "concept_001", "to": "concept_002", "type": "PRE_REQUISITE_OF" }  
> ]  
> }

### 第三步：人工审核（只审核心关系）

建立一张Excel审核表，重点关注：

|需审核的关系类型|审核要点|示例|
|---|---|---|
|`PRE_REQUISITE_OF`|**必审**：该依赖关系是否符合教学逻辑？|“时序逻辑”的前置真的是“组合逻辑”吗？|
|跨章节的`TESTS`|**抽审**：习题是否真的考察了该知识点？|“习题5.8”真的考察了“卡诺图”吗？|
|`BELONGS_TO`|**信任LLM**|无需审核|

> **工作量估算**：500页课本的核心`PRE_REQUISITE_OF`关系约200-500条，人工逐条审核约需1-2天。

### 第四步：入库（写入Neo4j）

python

from neo4j import GraphDatabase
driver = GraphDatabase.driver("bolt://localhost:7687", auth=("neo4j", "password"))
def create_node(tx, node):
    query = f"CREATE (n:{node['type']} {{id: $id, name: $name}}) RETURN n"
    tx.run(query, id=node['id'], name=node['name'])
def create_relationship(tx, rel):
    query = f"""
    MATCH (a {{id: $from}}), (b {{id: $to}})
    CREATE (a)-[:{rel['type']}]->(b)
    """
    tx.run(query, from=rel['from'], to=rel['to'])
with driver.session() as session:
    for node in nodes:
        session.execute_write(create_node, node)
    for rel in relationships:
        session.execute_write(create_relationship, rel)

## 三、RAG与知识图谱的协作关系

|环节|RAG的角色|知识图谱的角色|
|---|---|---|
|**用户提问**|将问题转为向量，检索相关段落|识别问题中的核心实体，查询前置知识链|
|**检索阶段**|ChromaDB返回Top-5相关段落（含图片URL）|Neo4j返回“该知识点依赖哪些前置知识”|
|**生成阶段**|大模型用检索到的段落编写回答|大模型在回答中主动提示“你可能需要先复习XX”|
|**最终效果**|回答有“事实依据”（课本原文+配图）|回答有“逻辑深度”（知道为什么学不会）|

## 五、一句话总结

- **RAG构建的本质**：把课本变成“可检索的碎片 + 可展示的图片”，让大模型能引经据典地回答。
    
- **知识图谱构建的本质**：把逻辑关系抽成“节点 + 边”，让系统能推理出“为什么”和“先学什么”。
    

两者结合，你的系统既能“博闻强识”（RAG），又能“逻辑清晰”（知识图谱），这才是真正的智能导师。
