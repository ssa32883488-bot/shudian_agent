## 1. 引言与目标

### 1.1 系统定位

学灵伴是面向高等教育《数字电子技术》的学科垂类智能应用。系统以**助学智能体为业务中枢**，在教材知识、题库与专业绘图工具约束下，提供伴随式问答、解题讲解、学情驱动练习与错题管理；并通过管理控制台完成题库经营、内容回流审核与班级学情分析。

架构命题不是「接入一个大模型」，而是将**学科规范、可信知识与可编排工作流**固化为可运营的助学系统。

### 1.2 质量目标

| 优先级 | 质量目标 | 架构含义 |
|--------|----------|----------|
| 高 | 学科可信 | 题库权威路径优先；AI 与权威分轨交付；结论可溯源 |
| 高 | 复杂任务可控 | 长任务计划化 + 人在回路；工具配额与超时 |
| 高 | 专业表达完备 | 数电图类经 IR + 确定性渲染 |
| 中 | 可观测可运维 | 轨迹可追踪；熔断与降级路径明确 |
| 中 | 可部署可复现 | 容器化；知识灌库与运行时依赖可说明 |

### 1.3 干系人视角

学生求「问得懂、解得对、图画得规范」；教师管理员求「题库可经营、班级学情可见」；技术评审求「架构清晰、可演进」。

---

## 2. 约束与阶段聚焦

**阶段聚焦**：本阶段优先做深助学中枢——问答、解题、出图、学情练习，以及管理侧题库经营与班级学情。教考协同、课程护航等作为下一阶段自然延伸，见第 9 章展望。

**技术约束**：单学科纵深；模型与工具分离；权威/参考信任不可混淆；BYOK 密钥不上服务器持久化。

---

## 3. 解决方案策略

采用「**中枢智能体 + 知识底座 + 经营面**」三元结构。编排层以有状态图描述解题流水线，以 ReAct 承载开放式工具使用，以路由层区分短/长路径。外层负责任务切片与人机闸门，内层负责权威检索与工具增强作答，汇入同一导师人格与工具注册表。

---

## 4. 上下文视图

```text
学生 / 教师管理员 → Web 应用 → API/编排服务
                         ├─ 向量检索（教材/题库）
                         ├─ 知识图谱
                         └─ 大模型与 OCR 网关
```

逻辑分层：展示层 → 接入层 → 业务层（FastAPI · LangGraph · 工具网关）→ 数据层。

---

## 5. 构建块视图

容器级：学生 Web、管理控制台、API 与编排、知识与检索、绘图工作流、持久化与媒体。

**智能体运行时四层**：感知 · 规划与路由 · 编排执行 · 护栏与可观测。

**工具注册表**：`draw_with_workflow`、`search_question_bank`、`retrieve_multi_rerank`、`graph_query`、`read_profile`、`memory_*`。

**知识底座**：离线灌库 / 在线检索解耦；教材切块、题库双通道、校本图谱。

## 6. 运行时视图

### 6.1 控制流

感知 → 意图路由（仅输出结构化路由结果）→ 短路径直达解题编排 / 长路径经人在回路确认后串行进入解题编排。

### 6.2 意图双模式

| 模式 | 适用情境 | 控制策略 |
|------|----------|----------|
| `react_short` | 寒暄、单点讲解、单题等 | 直接进入解题编排 |
| `plan_execute` | 多题、整卷、长文档、复合任务 | 任务清单确认后执行，支持续跑 |

### 6.3 解题编排图

```text
normalize → ocr_or_text → decide → scope_task → bank_prefetch
  ├─ 命中 → 权威交付
  └─ 未命中 → kg_ground → ai_solve → validate → 回流裁决
```

### 6.4 护栏

迭代深度、时间预算、工具配额、重复动作断路、输出规模限制；流式步骤事件 + 运维轨迹。

### 6.5 绘图工作流

统一门面 → 图类解析 → IR（脚本/槽位/生成）→ 结构校验与有限重试 → 确定性渲染 → DRAW 占位绑定。图类含逻辑图、波形、状态图、真值表/卡诺/七段、特性曲线、MSI 设计电路。

### 6.6 记忆

短期会话 · 长期记忆 · 学情画像。

## 8. 关键架构决策

| 决策 | 选择 | 后果 |
|------|------|------|
| 编排骨架 | 状态图 + ReAct | 分支/短路/循环显式化 |
| 任务形态 | 双模式 + HITL | 长任务可控、短任务低摩擦 |
| 权威策略 | 题库预取短路 + 交付分轨 | 可信度与回流飞轮 |
| 绘图策略 | 单门面 + IR + 确定性渲染 | 可回归的教材级出图 |
| 角色策略 | 助学中枢 + 管理经营面 | 先立助学深度；向教考协同平滑扩展 |

## 9. 未来迭代与产品展望

现行架构已形成可运行的助学中枢与内容经营闭环。后续沿「学得更深、教得更省、管得更清」延伸：课程护航、教考多智能体协作、校本适配与规模化样板。下列方向描述目标形态，作为路线图展望。

### 9.1 多智能体教考协同

在助学智能体旁侧生长考务智能体簇：组卷、发布—收卷编排、判卷初评与考次洞察；Orchestrator + Worker 拓扑；与助学中枢分工具域、分权限、分审计，并复用题库、学情与可观测基础设施。

### 9.2 课程制护航学习（Curriculum Agent）

课程状态机维护节次、目标、待练与掌握度；讲练评 + 苏格拉底互动 + 章末学情报告。与自由问答互补：一者护航有进度的学，一者支撑探究式问。

### 9.3 平台能力持续增强

校本大纲配置 · 图谱与评测集工程化 · 窄域图小模型降本路径 · 多班级规模化验证。

### 9.4 版本路线展望

打磨助学中枢 → Curriculum 单章闭环 → 教考协同试点 → 多智能体统一可观测 → 校本配置与规模化应用。

---

## 10. 小结

助学智能体为架构中枢，管理控制台完成经营与可观测。课程制护航与多智能体教考协同构成清晰产品展望，系统可在现有中枢之上平滑生长，持续服务「人工智能 + 一流学科」。
