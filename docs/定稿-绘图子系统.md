# 定稿 · 绘图子系统（Agent 可调用工作流）

> **生效**：2026-09-11  
> **定位一句话**：绘图不是独立产品，只是智能体解题时调用的 **出图工作流**。  
> **唯一工具**：`draw_with_workflow`（`backend/app/tools/draw_workflow/`）  
> **图类**：仅下列 **8 种**；无 `design_circuit` / `msi_counter` / 直调 Tier-B 工具 / Schematex 沙箱入口。  
> 冲突时以本文为准；旧文 `绘图工具工作流与开发历程.md` 仅作历程参考（已标 obsolete）。

## 1. 定位（是什么 / 不是什么）

### 是

```
用户题面 → tutor ReAct / Plan
         → 工具 draw_with_workflow(...)
         → 路由 kind → Skill → IR/参数 JSON
         → 结构校验 → 引擎出 SVG → /media/artifacts/...
         → 答案正文用 <<<DRAW ...>>> 占位，交付时换成图片 URL
```

- 产物统一：**SVG**（`gateway.save_svg_artifact` → `GET /media/artifacts/{file}`）
- 无独立「绘图 REST API」；出图是解题副作用
- 代码真源：`app/tools/draw_workflow/` + `app/tools/draw/`（runners 内部）+ `runtime/*_workbench`

### 不是

- 不是前端页面、不是教师出卷模块、不是独立 CAD
- **不做**框图 `block_struct`、泛原理图 `circuit_netlist`（已搁置）
- **不做**像素级复刻课本坐标；逻辑图看拓扑+国标符号，电路图看逻辑先行+布线规范
- **已删除 / 禁止再暴露**：`design_circuit`、`msi_counter`、`draw_kmap` / `draw_truth_table` 等直调工具、`draw_diagram`、`draw_schematex`、`render_by_llm_script`、xor/门符号例外工具、Schematex DSL 沙箱

## 2. 图类总表（仅 8 种）

| kind | 何时用 | 引擎 / 依赖 | IR / 参数 |
|------|--------|-------------|-----------|
| `logic_dag` | 门级逻辑图（全加器、异或基本门实现、表达式） | Node + `netlist_workbench` | `logic_ir_v1` |
| `timing_wave` | 多信号时序波形 | Node + `schematex_workbench` | `wave_ir_v1` |
| `state_machine` | 状态转换图 | Node + `schematex_workbench` | `state_ir_v1` |
| `truth_table` | 真值表 | 纯 Python | `inputs/outputs/rows` |
| `kmap` | 卡诺图 ≤4 变量 | 纯 Python | `minterms` + `var_count` |
| `seven_seg` | 七段数码管点亮 | 纯 Python | `digit` |
| `char_curve` | TTL/CMOS 传输特性 | Matplotlib | `curve=ttl_vtc\|cmos_vtc` |
| **`msi_design`** | **设计电路**：74 MSI / 555 / CMOS / DAC·ADC / 置零·加载·译码·MUX… | Java 17 + `Digital.jar` | `digital_msi_v1` + `logic_first` |

**硬规则（防智能体选错）：**

1. 凡「用芯片搭电路 / 置零法 / 加载法 / 555 / DAC / 模 N 计数」→ **只选 `msi_design`**。  
2. 凡「与或非门级连接 / 表达式 / 异或用基本门实现」→ `logic_dag`。  
3. 不确定 kind 时：`diagram_kind=""`，把题意写全到 `brief`，交给路由。

## 3. Agent 调用说明（调用卡）

### 3.1 唯一调用

```text
draw_with_workflow(
  brief="题意摘要：要画什么、关键约束、芯片/表达式",
  diagram_kind="",          # 能确定就填；不确定留空
  slots_json="",            # 已有结构化槽位可填，跳过部分 LLM
  script="",                # 已有完整 IR JSON 可填，跳过生成
  max_retries=3             # 1..3；结构校验失败后的修正轮次上限
)
```

正文步骤写占位（勿编造图片 URL）：

```text
<<<DRAW kind="msi_design" desc="74163 同步置零模7">>>
```

### 3.2 入参优先级（工作流内）

```
显式 script
  → 完备 slots_json（可当 IR）
  → 确定性 fallback（仅 timing_wave / truth_table）
  → LLM + 对应 skills/*.md
```

### 3.3 禁止 / 易错

| 错误 | 正确 |
|------|------|
| 调任何其它 `draw_*` 工具名 | 只用 `draw_with_workflow` |
| 设计电路用已删的 `design_circuit` | **`msi_design`** |
| `logic_dag` 传 Schematex 文本 | 传 `logic_ir_v1` JSON |
| 同一会话狂调出图 | 受 `AGENT_MAX_DRAW_CALLS`（默认 3）熔断 |
| 无 Java 时硬出 MSI | 环境先自检；仅 mod7 金标可 SVG 回退 |

### 3.4 运行时注入文档位置

| 给谁看 | 路径 |
|--------|------|
| Agent（每 kind） | `draw_workflow/skills/*.md` |
| Agent 总览 | `draw_workflow/skills/README.md` |
| Tool schema | `app/tools/lc_tools.py` → `DrawWorkflowArgs` |
| ReAct 系统规则 | `app/agents/tutor_react.py` → `DRAW_SYSTEM_RULES` |
| MSI 方法论 | `.cursor/skills/msi-design-circuit/SKILL.md` + `digital_dig/LIBRARY.md` |

## 4. 校验与防死循环

### 4.1 工作流内（单次工具调用）

```
for attempt in 0 .. max_retries-1:   # 默认最多 3 次，硬 clamp 1..3
    parse_script(JSON)
    verify_structure(kind)           # msi 另含 validate_logic_first
    dispatch_runner → 出 SVG
    失败 → 错误写入 feedback → 再生成 IR
仍失败 → wrap_err（含 attempts 日志）
```

实现：`draw_workflow/loop.py`、`verify.py`、`runners.py`。

语义（以代码为准）：**最多 3 次尝试**（含首次），不是「首次 + 再 3 次」。

### 4.2 会话 / 图层级

| 层 | 机制 | 配置 |
|----|------|------|
| 单次工具 | IR/结构校验循环 | `max_retries≤3` |
| 会话熔断 | 累计绘图工具次数 | `AGENT_MAX_DRAW_CALLS=3` |
| 交付检查 | 题面要图但无产物 → 压分/不回流 | `solve_graph.node_validate` + `draw_blocks` |
| 强制补图 | 缺图时旁路再渲 | `tutor_react` → **同样** `draw_with_workflow` |

### 4.3 当前不做

- 多模态「像不像课本」视觉打分（金标对照页人工验收）

## 5. 环境依赖矩阵（可移植核心）

### 5.1 按图类

| 依赖 | 图类 | 本机现状（开发机） | Docker / 第三方 |
|------|------|-------------------|-----------------|
| Python + matplotlib | Tier-B + char_curve | ✅ requirements | ✅ 镜像有 Python + matplotlib |
| **Node.js** | logic / wave / state | ✅ | ✅ `Dockerfile.backend[.slim]` 装 nodejs/npm |
| **netlist_workbench** | logic_dag | ✅ `runtime/netlist_workbench` | ✅ COPY `runtime/` + `npm ci` |
| **schematex_workbench** | wave / state | ✅ `runtime/schematex_workbench` | ✅ 同上 |
| **Java 17+** | msi_design | ✅ `JAVA_HOME` / PATH | ✅ slim 镜像用 `openjdk-17-jre-headless`（bookworm） |

| **Digital.jar** | msi_design | ✅ `DIGITAL_JAR` 或 `vendor/` | ⚠️ 部署挂载 / 放入 vendor（不强制进 Git） |

查找逻辑：

- workbench：`DRAW_RUNTIME_ROOT` → `shudian_agent/runtime/` → `/app/runtime` →（兼容）`_archive/`
- Digital：`DIGITAL_JAR` / `DIGITAL_HOME` → `digital_dig/vendor/Digital.jar` → 邻近 `digital-circuit-poc`
- Node / Java：`NODE_BIN` / `JAVA_HOME` 或 PATH（**无本机绝对路径硬编码**）

> 仓库根 `_archive/*_workbench` 仅作本机旧布局回退；正式发布以 `runtime/` 为准。

### 5.2 环境变量（须写入 `.env`）

```bash
# 绘图运行时
DRAW_RUNTIME_ROOT=                 # 可选；Docker 内为 /app/runtime
NODE_BIN=node
JAVA_HOME=                         # 或保证 PATH 有 java
DIGITAL_JAR=F:/path/to/Digital.jar
MEDIA_BASE_URL=...                 # 产物 URL 前缀
AGENT_MAX_DRAW_CALLS=3
MIMO_*                             # Skill→IR 的 LLM；无 Key 时质量差/mock
```

自检：

```bash
cd shudian_agent/backend
python -m scripts.check_draw_runtime
python -m scripts.smoke_all_draw_kinds   # 全图类冒烟（需依赖齐全，含 Digital.jar）
```

本机首次：

```bash
cd shudian_agent/runtime/netlist_workbench && npm ci
cd ../schematex_workbench && npm ci
```

## 7. 与产品其它部分的边界

- 智能体核心：`agents/tutor_react.py` + `graphs/solve_graph.py`  
- 绘图失败不应拖死整题：返回明确错误；会话熔断后改用文字描述电路  
- 管理端 / 学情 / 练习 **不**直接调绘图引擎  
- 教材插图 RAG（`<<<FIGURE>>>`）≠ 本子系统出图（`<<<DRAW>>>`）
