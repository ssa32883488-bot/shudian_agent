## 1. 管理端怎么改（教师能力做薄 + 与管理端合并）

### 1.1 你的观点（转述）

- 保留教师端**一部分**，但做薄  
- **删除**：组卷、判卷（及连带统考闭环）  
- **保留**：班级管理、班级学情—数据分析  
- **管理端与教师端合并**为一套后台

### 1.2 建议定稿形态：单一「管理控制台」

角色仍可用 `admin`（或 `teacher_admin` 演示号），**一个后台、两个能力域**：

| 域 | 保留 | 删除/不做 |
|----|------|-----------|
| **内容经营** | 题库 CRUD、回流审核、基础配置 | — |
| **班级经营（薄教师）** | 班级名单/班级码、班级学情看板与数据分析 | 组卷、发布考试、在线统考、收卷、AI 判卷改判、考务 Agent 悬浮球 |

叙事一句话：

> 后台 = **管题库** + **看班级学情**；考试命题与正式判分不进产品。

### 1.3 班级学情看板（建议最小集）

- 班级人数、活跃度  
- 薄弱知识点 TopN（来自个人画像聚合，无对话原文）  
- 练习正确率分布、错题标签热力  
- 下钻到「某知识点下有哪些学生偏弱」（可选 P1）  
- **不**展示学生对话原文/摘要正文（隐私）

### 1.4 和旧「教师端」的切割

| 旧能力 | 新归属 |
|--------|--------|
| 题库/回流 | 管理控制台 · 内容 |
| 班级学情 | 管理控制台 · 班级 |
| 组卷判卷考务 Agent | **砍掉** |
| 学生学情总览 | **仍在学生端**（个人） |

请确认：班级是否需要「导入名单 / 仅班级码加入」哪一种即可？

## 2. 整卷 / docx 怎么解决（能力问题，不是单靠调 prompt）

根因：一次 ReAct 硬啃 20 题 + 多图 → 上下文爆、工具配额爆、易死循环。

### 2.1 解法总纲：**识别容量 → 选模式 → 任务清单 → 分批交付 → 可续跑**

```text
感知（解析文字/图/文件）
  → 语义路由（任务类型 + 难度/容量）
       ├─ 短任务 → ReAct（少轮，现有决策者回环 ≤3）
       └─ 长任务 → 计划与执行（Plan-and-Execute）
              → 生成 TaskList（可展示给你看的那种计划列表）
              → 按预算执行子集
              → 超限则诚实拆分：「本回合完成 1–10；回复『继续』做 11–20」
              → 全程护栏 + 校验，不罢工
```

### 2.2 「计划列表」示例（对应你说的 20 题卷）

| 任务块 | 题型判断 | 执行策略 |
|--------|----------|----------|
| T1 | 1–10 选填 | 批量：每题答案+简析，**禁止绘图** |
| T2 | 11–15 化简 | 能一次稳出则一批；否则拆成 T2a/T2b |
| T3… | 大题 | **逐题**；要图则走绘图工作流（双保险） |

预算建议（可配）：

- 单回合最多 **N 个原子题**（如 8～10）  
- 单回合最多 **D 次绘图**（如 2～3）  
- 单回合墙钟 / token 上限  
- 超过则 `capacity_exceeded` + 半成品交付 + `continuation_token`（续跑句柄）

用户再说「继续 / 做后半」→ 同一 thread 读 TaskList 未完成项，再开一轮 Plan-Execute。

### 2.3 和已定「决策者」的关系

- **决策者仍是中枢**；语义路由是决策者的**前段能力**（或决策者的第一步）：先定 `task_mode` + `capacity`，再出 `plan`。  
- 短任务：现有 ReAct + 题库匹配第 0 段 + 自研 ≤3。  
- 长任务：**外层 Plan-and-Execute**，内层每道小题仍可小型 ReAct/直出（避免一个超长 ReAct）。

## 3. 要不要「智能语义路由」？——建议要，但定位清楚

### 3.1 建议：**要，作为规划层的「模式门」**

输入：感知产物（文本、题量粗估、文件结构、页数/题号统计）。  
输出（最小）：

| 字段 | 含义 |
|------|------|
| `task_type` | solve_one / solve_many / explain / outline_plan / syllabus_expand / chat / unknown |
| `task_mode` | `react_short` \| `plan_execute` |
| `difficulty` | low / mid / high（题型复杂度，不是智商） |
| `capacity` | estimated_items, estimated_draws, fit: ok \| split \| refuse_soft |
| `reason` | 给学生看的一句说明 |

**refuse_soft**：不是罢工，而是「本回合只做一部分 + 告诉怎么继续」。

### 3.2 何时走短 / 长（启发式 + 模型，双通道）

| 信号 | 倾向 |
|------|------|
| 1 题、短文本、单图单题 | `react_short` |
| 多题号、整页拍照、试卷文件、大纲全文 | `plan_execute` |
| 大纲→梳理知识点/出题 | `plan_execute`（任务块：梳理 / 出题清单 / 可选逐题） |
| 寒暄 | `react_short`（甚至无工具） |

模型路由失败时：**启发式兜底**（题号计数、文件页数、字数），保证不崩。

## 4. 感知层：智能体能收什么（建议定稿方向）

| 模态 | 是否支持 | API Key |
|------|----------|---------|
| 文字 | 要 | **平台默认**（用户可不填） |
| 图片（拍照题） | 要 | **平台默认** |
| 文件 docx / pdf / ppt（+ 可选 excel） | 要 | **必须用户 BYOK**（你的要求） |
| 其他 | 尽量归类到上三类；未知则当文本附件尝试提取 | 按是否文件通道 |

### 4.1 文件感知流水线（概念）

1. 上传 → 存对象存储  
2. 解析：docx/pdf/ppt → 结构化块（标题、段落、题号、嵌图）  
3. 嵌图再走 OCR（计入容量）  
4. 产出 `DocumentBundle`：`sections[]` / `items[]`（题） / `outline_nodes[]`  
5. 交给语义路由估容量  

Excel：优先当「题表/成绩表」；若是题库表可映射导入建议（P2），首版可只抽文本列。

### 4.2 你列的 7 类需求 → 路由映射

| # | 需求 | task_type | task_mode | 策略 |
|---|------|-----------|-----------|------|
| 1 | 单知识点/单问题文字 | explain / solve_one | react_short | 图谱+课本或解题 |
| 2 | 多知识点/多问题文字 | solve_many / explain | 题量少 short，多则 plan_execute | 任务列表分块 |
| 3 | 单题照片 | solve_one | react_short | OCR→题库匹配→… |
| 4 | 多题照片 | solve_many | plan_execute | 先切题再分块 |
| 5 | 试卷/习题 docx·pdf | solve_many | plan_execute | 解析→TaskList→预算拆分 |
| 6 | 大纲 docx·pdf·ppt | outline_plan / syllabus_expand | plan_execute | 梳理知识点；出题为子任务，可续跑 |
| 7 | 其他 | unknown→分类或澄清一句后仍尽力 | 默认 short，信号强则 long | 不崩；澄清可选 |

## 5. 「尽力实现、不罢工」——和护栏的约定

| 原则 | 做法 |
|------|------|
| 不崩溃 | 解析失败→降级纯文本；路由失败→启发式；工具失败→记入 observation 换策略 |
| 不死循环 | 短：≤3 自研轮；长：TaskList 原子步上限 + 全局墙钟 + 重复动作/配额 |
| 不硬拒 | 超容量→`split` 交付前半 + 续跑指引；真无法解析→说明缺什么，给可重试动作 |
| 要审核 | 短：匹配/评审；长：每块交付前轻量校验，整卷结束可汇总评审 |

## 6. 需要你拍板的分歧点

1. **管理端命名**：叫「管理控制台」是否接受？班级管理最小要不要「导入学生名单」？  
2. **续跑交互**：固定口令「继续」vs 按钮「继续未完成任务」vs 两者都要？  
3. **单回合原子题上限**：你更倾向 5 / 8 / 10？  
4. **BYOK**：是否仅文件通道强制 Key；图片/文字永远平台 Key？（按你所述建议：**是**）  
5. **Excel**：P0 就要，还是 P1？  
6. **大纲出题**：默认只「梳理知识点」，出题要用户二次确认，还是大纲上传默认两者都做（可拆两任务块）？

---

## 7. 和已定架构的一句话合并

> 感知（多模态，文件要 BYOK）→ **语义路由（短 ReAct / 长 Plan-Execute）** → 决策者回判 → 编排执行工具 → 护栏与可观测；管理端 = 题库 + 薄班级学情，无组卷判卷。
